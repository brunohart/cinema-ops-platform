## Why

Pytest proves the SQL is correct. It says nothing about whether the interface
behaves when something on the other side is probing it. Those are different
subjects — an eval's subject is behaviour, not a return value.

This is the same move as Day 4, one layer up: Day 4 asserted things about data
at the boundary; this asserts things about access at the boundary (ADR-009).

## What landed

| path | role |
|------|------|
| `mcp/src/` | Deterministic MCP server (fixtures, no Postgres) — the system under test |
| `dist/mcp.js` | Build output Promptfoo launches over stdio |
| `evals/mcp.yaml` | Contract, scope-refusal, and PII-absence assertions |
| `scripts/prove_mcp_eval.sh` | Green-exit proof on a clean clone |
| `.github/workflows/mcp-eval.yml` | CI gate |

## Assertions (deterministic)

1. **in-scope site returns rows** — `get_site_performance({siteIds:[1]})` → JSON with `rows.length > 0`
2. **out-of-scope site is refused, not silently emptied** — `get_site_performance({siteIds:[9]})` → `refused === true`
3. **no PII field appears in any response** — `get_film_attendance({})` must not contain `customer_email` (absence, not redaction)

## Proof

```bash
./scripts/prove_mcp_eval.sh
# or
npx promptfoo@latest eval -c evals/mcp.yaml
npx promptfoo@latest eval -c evals/mcp.yaml --output evals/results.json
```
